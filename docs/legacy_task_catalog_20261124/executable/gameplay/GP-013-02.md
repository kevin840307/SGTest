## 2026-11-25 v14 實際證據
- `SGOEquip::ReadWeaponData` 已 DIRECT 確認 `Dat/Item/Weapon.itd` 每筆固定 1247 bytes（`1 + 0x2A + 0x34 + 8 + 0x478`）；真 Old 檔 91,031 bytes 正好 73 筆、無尾端殘值。
- `SGOItemData::SearchIndex` 確認 internal WORD[1]=`ItemIndex`；`SGOWeaponData::SearchIndex` 由 parent WORDSIZE=25、total WORDSIZE=27 與欄位表 `UseItem, AttDistance` 確認 WORD[25]=`UseItem`、WORD[26]=`AttDistance`。正式 converter `weapon-attack-ranges` 因此可 source-audited 解析，不依數值分佈猜 offset。
- 新增正式 `weapon-definition-ranges` 三方 bridge：重新唯讀 SGTest converted `Items/*.tres`、HK `Item/item.itd`、Old `Weapon.itd`，只接受「SGTest unique exact-name → HK item id → Old ItemIndex」且 converted `attack_range == Old AttDistance` 的一對一規則；不把 presentation-only `client/content/item_catalog.json` 升格成 Server authority，任何名稱歧義、range 不一致、重複 identity 均 fail-closed。
- 真實來源 publication PASS：SGTest 5,003 items／1,282 weapons，HK unique-name 3,038、HK weapon matches 1,274；Old 73/73 全部閉合為 SGTest `item_definition_id -> old_item_index -> attack_distance`，包含先前未閉合的 Old `1587 -> Definition 31548 -> 140`；unresolved=0，距離集合仍為 `{60,90,100,120,140,350}`。Python bridge/item/Old parser targeted **13/13 PASS**。
- Server 新增 `WeaponAttackRangeCatalog.LoadVerified`，只接受完整 `partial=false`、73/73 audit 一致、Definition/Old ID 唯一、range 1..500、SHA256 合法的 manifest；synthetic Server gate **3/3 PASS**（完整規則接受、partial unresolved 拒絕、重複 Old identity 拒絕）。Unknown definition 維持不存在，供 runtime 繼續 fail-closed。
