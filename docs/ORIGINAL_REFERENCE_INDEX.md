## 3. 缺圖時的取得順序（隨當前開發任務）

1. 查本索引、原始目錄和既有私有 evidence；實際開相符原圖，不反覆讀全部。
2. 缺目標畫面/狀態：唯讀 HK output\Interface、UI_CONTROL_METADATA.json / SPR_FRAME_METADATA.json、Data1_PNG2 → Data1_PNG → Data1.dat → loose SPR；查 SGOClient.exe.lst 實際 Create/Draw/MessageMap/control handler、frame-state、文字與開關。原版 Client 可安全操作時，以 C:\SGO\SGO Paradise\program\client.exe 既有授權測試帳號，正常鍵鼠進目標，補初始/有資料/空/disabled/hover/pressed/selected/確認/取消/錯誤/動態影格；交易、社團等使用隔離且有權限的角色。不得影響真實帳號資產、其他玩家或使用者測試視窗；不輸出憑證，不未經授權改原版資料。
3. 原版互動不可用：依 C:\SGO\Recovered\Old\ClientData\Paradise.exe.lst、Old 服務端\plugins\*.dll.lst、Dat/cfg/game.sql、C:\SGO\Recovered、C:\SGO\NewVersion\Recovered2、C:\SGO\SGOAuto 交叉確認，原版來源唯讀。可用原素材組合的診斷 reference reconstruction，但標 SYNTHESIZED/NOT LIVE，不偽造實拍或 pixel PASS。依已驗證來源實作正式垂直切片；未知畫面/行為 NOT VERIFIED，記缺口與下一步。
4. 補圖存本機 git-ignored .cache/ui-parity/reference/<TaskID>/，保存版本、日期、入口/狀態、原始 client area/DPI、影格與必要 trace，原圖目錄不改。更新本索引對應組的證據摘要/路徑或既有 Task MD；不把原圖/私有帳號/二進位推 Git。有效證據重用。
5. 同一任務繼續正式實作與操作驗收；補圖或抽取 .lst 不是玩家交付。工具兩次失敗按 AGENTS fallback，缺證據具體記錄，不反覆卡在盤點。

## 4. 功能與畫面雙驗收（全部 UI）

每個可達畫面/子窗/控件追：原版入口/前置 → control ID/rect/frame/font → 原版事件/規則/資料/分支 → 正式 Client input/focus/hitbox → intent/封包 → Server 權威/交易 → 回覆/更新 → 可見 UI/世界動畫/成敗提示 → 適用雙 Client/重登。正常/拒絕/取消/關閉/重開/換圖/斷線及權限/併發按功能驗證。純本地設定/拖移亦驗實際本地效果。

- 實際開原圖找同狀態，HK 優先 ITF/SPR/PNG/.lst；逐控件校正，不做 screenshot skin、不猜字型或尺寸。
- 控件有圖無 handler、empty Callable、任意禁用可達原版功能、只切換選中圖、沒有真物品/角色、fixture、headless、手工觸發 signal 均不得當完成。
- 正式 Server + 可見 Godot Client + 真鍵鼠，照原版流程操作；UI 與 Gameplay Gate 獨立判定，同時適用皆通過才 COMPLETE，另加適用 Multiplayer/Performance/Persistence。缺圖不等於無需驗，外觀 PASS 不等於功能 PASS。
- 交接只需既有 Task ID/玩家成果、reference/Before/After/trace、各 Gate、缺口/下一動作，不重寫規格或另造完成度表。
